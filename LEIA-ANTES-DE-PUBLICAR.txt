SISTEMA DE MADEIRAS — V683 ASSINATURA DE ENTREGA

O pacote contém o site e a função de servidor que gera e valida o código e grava a assinatura no pedido correto. O link não leva o código. O cliente abre o link, informa nome e código de 8 dígitos, desenha a assinatura e confirma. O convite não expira por tempo; fica válido até ser assinado. Se o funcionário fechar a janela, o pedido entregue mantém a opção “Ver link e código da assinatura”.

CONFIGURAÇÃO SEGURA NO NETLIFY
1. Configure duas variáveis privadas no projeto Netlify:
   - FIREBASE_SERVICE_ACCOUNT_JSON: JSON da conta de serviço criada no projeto Firebase estoque-madeiras-cc4d7. A conta precisa do papel Cloud Datastore User para ler e atualizar pedidos no Firestore.
   - DELIVERY_SIGNATURE_SECRET: segredo aleatório e estável de pelo menos 32 caracteres. Guarde-o em local seguro e não o coloque no HTML, no ZIP nem em mensagens. Não o troque enquanto houver convites pendentes.
2. Publique a pasta completa usando um deploy com build do Netlify (por repositório Git ou Netlify CLI). Arrastar somente o HTML para o Netlify Drop publica apenas a tela e não instala a função.
3. Depois de a função aparecer no deploy, teste com um pedido confirmado de teste. A entrega deve ficar marcada como entregue e aguardando assinatura. A assinatura só muda para “Assinado por…” depois do cliente enviar nome, código e assinatura desenhada. No pedido assinado, “Ver assinatura” mostra o desenho. Pedidos assinados anteriormente continuam válidos mesmo sem desenho.

A função valida o login do funcionário e o vínculo ativo da empresa. As regras do Firestore não são alteradas e a página pública do cliente não lê o banco diretamente.


TESTE DA ASSINATURA DESENHADA
Abra o link de um pedido de teste no celular. Confira que não permite confirmar com o quadro vazio, desenhe com o dedo, teste Limpar assinatura, assine novamente e confirme com nome e código. No sistema, confira o nome, a data e a opção Ver assinatura no pedido entregue. Código incorreto deve preservar o desenho para nova tentativa.

Os convites pendentes continuam usando o mesmo link e código. As novas confirmações exigem o desenho. A imagem é formada por coordenadas numéricas validadas no servidor e gravada junto ao pedido na mesma transação. Não requer Firebase Storage nem novas variáveis no Netlify.

BUILD DO SITE
O Netlify executa npm run build para acrescentar a tela de desenho e a visualização no HTML legado. Para testar localmente, execute npm run build antes de servir a pasta public. O arquivo scripts/build-signature.mjs verifica os trechos esperados e interrompe o build caso o HTML base mude.
